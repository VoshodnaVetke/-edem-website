# ЭДЕМ | ВНУТРЕННИЕ ПРАВИЛА ДИЗАЙН-СИСТЕМЫ
## Spacing & Layout v1.0 · Сетка и правила адаптации

**Дата утверждения архитектуры:** 28 октября 2026 года.  
**Статус:** **APPROVED** — схема **4/8/12 + CSS Grid auto-fit + внутренние Container Queries**.  
**Точный статус чисел:** отступы и зазоры ниже — стартовые технические токены для внедрения, пока не подтверждены отдельным оптическим тестированием; размеры семейств карточек из `EDEM_LAYOUT_CARDS_V1_DRAFT.md` пока **DRAFT**, а не окончательные утверждения.  
**Эталоны:** `edem-interface-cyberpunk-v55-onest.html` (графика), `edem-typography-v1.css` (типографика «Баланс B»), `EDEM_SITE_DESIGN_SYSTEM_V55_TYPOGRAPHY_V1_APPROVED.md` (основная утверждённая спецификация).

## 1. Три разных уровня компоновки

1. **Внешняя сетка страницы:** 4/8/12 направляющих, исходя из ширины viewport. Используется для общей композиции и асимметричного деления (например, на десктопе 7/12 + 5/12).
2. **Автосетка коллекции карточек:** `display:grid` и `repeat(auto-fit, minmax(min(100%, …), 1fr))`. Число карточек в ряду определяется шириной доступного контейнера и предпочтительной шириной карточек, а не командой «всегда 3 на компьютере».
3. **Внутренние контейнерные правила:** `container-type:inline-size`, `@container`. Реагируют на реальную ширину компонента, чтобы регулировать внутренние интервалы, переносы и второстепенные декоративные элементы независимо от viewport.

**Запрещено** подменять этими тремя механизмами друг друга. Глобальная сетка отвечает за композицию страницы; автосетка — за повторяющуюся коллекцию; контейнерные запросы — за собственное содержимое карточки.

## 2. Брейкпоинты и начальные токены

| Параметр | Телефон ≤650 CSS px | Планшет 651–1023 CSS px | Десктоп ≥1024 CSS px |
|---|---:|---:|---:|
| Колонки внешней сетки | **4** | **8** | **12** |
| Внутренний отступ основного контейнера | 16px | 24px | 32px |
| Зазор между направляющими колонками | 12px | 16px | 24px |
| Зазор между карточками | 14px | 16px | 20px |
| Максимальная внешняя ширина контейнера | ширина viewport | ширина viewport | 1180px, **включая** padding |

Для документации и CSS брейкпоинты выражены в `rem` с привязкой к 16 CSS px; пользовательское масштабирование не блокируется. Интервалы являются базовыми токенами для нового layout-слоя, но не требуют механической замены всех исторических внутренних отступов v55.

## 3. Примеры общей композиции

- **Десктоп:** вводный блок на 7/12, боковой модуль на 5/12; следующая строка компактных карточек может содержать 3 элемента по 4/12. Главная композиция без внешней рамки, как в v55.
- **Планшет:** вводный блок занимает 8/8; две карточки по 4/8, если обе помещаются с безопасным контентом; сложная карточка может занимать все 8/8.
- **Телефон:** все основные контентные блоки 4/4, одна карточка в ряд; минимум ширины компонента не должен вызывать горизонтальную прокрутку.

Эта схема — правила переиспользования, **не новая утверждённая структура главной страницы**.

## 4. Карточки: компактность, адаптивность и статус размеров

**Утверждённый принцип:** без искусственного растягивания на высоту ряда (`align-items:start`, `align-self:start`); без жёсткого `max-height` для обязательного текста; полная доступная ширина до собственного ограничения `max-inline-size`. Карточка растёт только из-за содержания, переноса текста или функциональных элементов.

**Размерные ориентиры из ранее подготовленного DRAFT** (отдельно ещё не утверждены):

| Семейство | Желательная минимальная ширина в коллекции | Предельная ширина | Высота ориентировочно |
|---|---:|---:|---|
| Compact | 260px | 400px | 130–200px |
| Terminal | 300px | 460px | 220–310px |
| Loader | 280px | 380px | 260–340px |
| Action | 260px | 420px | 110–190px |
| Complex/Form | 300px | 520px | по содержимому |

Предпочтительная ширина ячейки автосетки **может быть больше минимальной ширины карточки** для аккуратной композиции (например, `320px` для Compact или `336px` для Terminal). На узком телефоне автосетка сжимается до `100%` доступной ширины. Никаких принудительных `min-width:300px` на элементе при viewport 320px.

### Особенности геометрии v55

- Сохраняются все три SVG-семейства `system`, `double`, `asym`, деликатные Rough.js-обводки и функции анимации.
- Для сложных рамок отдельно определить безопасные поля каждой формы после визуального теста с Tektur и Onest. Простое уменьшение `padding-top` из v55 без проверки приводит к наложению на системные надписи и диагонали.
- `LINK // 03` и круговой индикатор — отдельная flex-строка без наложения; на узких экранах скрывать можно лишь необязательную декоративную информацию.
- Состояния `hover`, `focus-visible`, touch, loading и reduced-motion не меняются в результате внедрения новой сетки.

## 5. Реализация

Файл: **`edem-layout-v1.css`**. Он содержит:

- `--edem-layout-columns`, `--edem-layout-padding`, `--edem-layout-gutter`, `--edem-card-gap`, `--edem-layout-max`;
- внешнюю `.edem-layout` и `.edem-layout-grid` с семантическими span-классами;
- `.edem-gallery` с модификаторами предпочитаемой ширины;
- `.edem-card` и размерные модификаторы (пока DRAFT) и внутренний `@container edem-card`;
- запрет жёсткого роста карточек по высоте.

Пример: **`EDEM_LAYOUT_GRID_V1_EXAMPLE.html`**. Демонстрирует три ширины и компактную композицию. Это иллюстрация правил сетки, не альтернативная версия утверждённых геометрий v55.

## 6. Проверки при переносе на реальные компоненты

Проверять ширины 320, 360, 390, 430, 650, 651, 768, 1023, 1024, 1280 и 1440 CSS px; увеличение текста до 200%; длинные слова, ошибку формы и загрузку; отсутствие горизонтального скролла; сохранность декоративных линий и доступность фокуса. Фактическая визуальная проверка переносимых сложных карточек — отдельный этап.

## 7. Защита утверждённых решений

**Не менять** Typography v1.0 «Баланс B», палитру, фон, геометрии, принципы движения, 5 разновидностей загрузчиков, правила mobile touch и назначение трёх шрифтов. Эталон v55 остаётся неизменным до контролируемого переноса. Новые страницы не обязаны копировать демонстрационную композицию v55.
