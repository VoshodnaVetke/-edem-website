# ЭДЕМ | Navigation C v1.2 — предварительная фиксация

**Дата:** 28 октября 2026 года  
**Статус:** ПРЕДВАРИТЕЛЬНО СОГЛАСОВАНО (`PROVISIONAL`), НЕ ФИНАЛ  
**Эталон прототипа:** `EDEM_NAVIGATION_C_V1_2_TOP_BURGER.html`  
**Основа:** графическая дизайн-система v55, Typography v1.0 «Баланс B» (APPROVED), Layout Grid v1.0 4/8/12 (APPROVED).

## 1. Цель и общий принцип

Мобильная версия — основной сценарий использования публичного сайта. Навигация должна помогать быстро переходить к главным направлениям и не забирать у контента чрезмерную высоту экрана.

Выбранный подход **C (гибрид)**: верхняя шапка для глобальных инструментов и полного меню; нижняя мобильная панель для частых направлений. Это принцип навигации, не финальная информационная архитектура сайта.

## 2. Верхняя шапка

- Логотип «ЭДЕМ» — визуальный якорь; ссылка на основную страницу должна быть предусмотрена при подключении реальных маршрутов.
- **Бургер** — открывает общее иерархическое меню. На мобильном расположен в шапке, а не в нижней панели.
- **Поиск** — рядом с другими служебными действиями; искать должен опубликованные объекты (игры, статьи, персонажи, организации), а не список разделов.
- **Личный кабинет** — рядом с поиском **на всех ширинах**. На узких устройствах разрешена иконка с доступным текстовым названием; на просторных экранах возможны иконка и подпись.
- Действия в шапке должны иметь достаточный размер сенсорной области; сам текст не должен уступать место чисто декоративным кодам.

## 3. Нижняя мобильная панель

**Три быстрых раздела:** `Афиша` · `Мир` · `Энциклопедия`.

- Нет повторного пункта «Меню» (бургер находится в шапке).
- Нет «Кабинета» (он находится в шапке).
- Показывается явное активное состояние, включая текстовую подпись; цвет не единственный признак активности.
- Не должна перекрывать контент; учитывается безопасная зона устройства `env(safe-area-inset-bottom)`.
- Для планшета и десктопа нижняя панель **не обязательна**: используется горизонтальная навигация по доступной ширине, прочие разделы — в меню.

## 4. Меню и поиск — разные функции

### Меню

- Предназначено для ориентации по структуре сайта.
- Предварительная иерархия прототипа: `Главное` → Афиша / Вселенная / Энциклопедия; `Мастерская группа` → О группе / Команда / Контакты.
- **Названия и вложенность не утверждены окончательно.** Возможна дальнейшая перестройка дерева разделов.
- При открытии меню доступность фокуса, Escape, возврат фокуса на вызвавший элемент должны сохраняться.

### Поиск

- Предназначен для поиска по **опубликованному содержимому**, а не для фильтрации пунктов меню.
- В нынешнем HTML результаты демонстрационные; поисковый индекс и реальные данные не подключены.
- Пустой запрос не должен превращаться в копию глобального меню. Нельзя представлять пример результатов как реальный результат поиска.

## 5. Адаптивные режимы

| Ширина viewport | Верх | Низ |
|---|---|---|
| Смартфон ≤650 CSS px | логотип + бургер + поиск + кабинет | Афиша / Мир / Энциклопедия |
| Планшет 651–1023 CSS px | сокращённая верхняя навигация + меню + поиск + кабинет | без постоянной нижней панели |
| Десктоп ≥1024 CSS px | видимые основные ссылки + меню + поиск + кабинет | без постоянной нижней панели |

Сохраняется утверждённая сетка **4/8/12**, CSS Grid для компоновки контента и Container Queries для внутренних компонентов. Изменять графический язык v55 не требуется.

## 6. Что не утверждено

- Финальное название каждого раздела и его место в информационной архитектуре.
- Маршруты публичного сайта, авторизация и данные личного кабинета.
- Реальный поиск, индексация, фильтры, источники и права доступа.
- Точные пиксельные параметры шапки, нижней панели и иконок (их предстоит закрепить после визуального тестирования).
- Окончательная React/TypeScript реализация (её пока нет).

## 7. Обязательная проверка перед окончательным утверждением

320, 360, 390, 430, 650, 651, 768, 1023, 1024, 1280, 1440 CSS px; портретная и альбомная ориентации; клавиатура и screen reader; 200% масштаб текста; safe-area; открытие/закрытие диалогов; состояния hover/focus/active; отсутствие ложного hover на сенсорных экранах; доступность всех разделов без JS как отдельная задача progressive enhancement.
